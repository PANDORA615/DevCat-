# Сборки и подпись

Workflow `build.yml` создаёт проверенные desktop-пакеты и Android build inputs. Публикация выполняется отдельно после проверки; не выкладывайте debug-signed Android inputs под видом production APK.

## Android

Текущий релиз подписывается постоянным RSA-4096 ключом `devcat`, хранимым вне git. Ключ и пароль должны остаться у владельца: без того же ключа нельзя установить обновление поверх APK. Резервная копия передаётся владельцу отдельно и не входит в GitHub Release.

Для следующих CI-сборок владелец может добавить Secrets:

- `ANDROID_KEYSTORE_BASE64`: base64 файла JKS, alias `devcat`.
- `ANDROID_STORE_PASSWORD`: пароль JKS.
- `ANDROID_KEY_PASSWORD`: пароль ключа.

Текущая интеграция GitHub не имеет доступа к Actions Secrets (HTTP 403), поэтому они не создаются автоматически. Скрипт `android_signing_config.py` читает их без вывода значений; Gradle использует окружение. Не фиксируйте `release.jks`, `key.properties`, `owner-signing.enabled` или пароли в git.

При отсутствии Secrets inputs подписываются временным debug-ключом среды и требуют переподписи постоянным ключом вне CI: APK — `apksigner`. Затем проверьте `apksigner verify --print-certs`. Сертификат должен совпадать для всех ABI. В 0.6.0 выпускается один universal APK с тремя архитектурами и всеми локальными средами. Split APK прежних выпусков сохранены как история.

## Desktop

Windows: Inno Setup installer и ZIP x64; Authenticode NOT_CONFIGURED. macOS: ZIP и DMG, ad hoc codesign; Developer ID/notarization NOT_CONFIGURED. Для магазинной или доверенной коммерческой поставки владелец должен предоставить свои сертификаты через секретное хранилище, не в репозиторий.

Linux: сборка на Ubuntu 22.04 для glibc ≥2.35. Deb/RPM/Arch metadata включают runtime dependencies. AppImage содержит приложение и Flutter, но требует системные GTK 3, GStreamer, libsecret; это явно указано в README.

## Проверка перед публикацией

1. Успешны analyze/test и сборки каждого выпускаемого пакета.
2. В артефактах нет ключей, локальных данных пользователя, паролей и debug Android inputs.
3. Составить SHA256SUMS по фактическим файлам.
4. Опубликовать prerelease с точными ограничениями и ссылкой на validation report.
5. Не называть CI-сборку проверкой на реальных Windows/macOS/Android устройствах.

Публичный сертификат текущего Android-ключа: [android-release-cert.pem](android-release-cert.pem). SHA-256: `F4412CFC2567A7B33248DF99777C0D104761DD2DDA3EE7DE8FE8BAC467098BCA`.

Для локальной переподписи: `python3 scripts/sign_android.py INPUTS OUTPUT --keystore /private/devcat.jks --password-file /private/password.txt --build-tools /path/to/android/build-tools/36.0.0`. Скрипт выравнивает APK для страниц 16 КиБ, проверяет подпись и не выводит пароли.

## Публикация 0.1 из managed environment

Текущая учётная запись среды позволяет Git/API, но отклоняется `uploads.github.com`. Публикацию выполняет отдельный `publish.yml` с минимальными `contents: write` и `actions: read` в GitHub Actions. Native-пакеты берутся из зафиксированного успешного build run. Уже подписанные Android-файлы переданы небольшими **публичными бинарными Git blobs без включения в дерево исходников**; manifest содержит только SHA и размеры. Это временный транспорт для открытых установщиков, не хранение ключей. Обычный clone не включает эти бинарные объекты в историю файлов.

Publisher проверяет исходный commit, успешность CI и все SHA256SUMS до загрузки. Приватный keystore и пароли в Actions не передаются. Для будущих версий предпочтительна настройка owner signing Secrets и обычная публикация из CI; staging manifest относится к 0.1.0.

## Публикация 0.2 и следующих версий

Publisher принимает версионированный manifest `docs/releases/vX.Y.Z-transfer.json` с успешным build_run, точным build_commit и публичными подписанными Android-байтами. Workflow считывает номер CI из manifest, загружает native artifacts, сверяет исходники и все SHA256SUMS, затем публикует prerelease. Ключ и пароль остаются вне GitHub. Metadata 0.1 сохранены как история.

В 0.2.1 split APK используют versionCode arm64 2003, ARMv7 1003 и x86_64 4003. Они обновляют соответствующий split 0.2.0 (2002/1002/4002) и старый universal (2). Выбирайте ABI установленного приложения.

Перед сборкой Android workflow создаёт ABI-образ из закреплённых архивов и подписанных Debian-репозиториев, собирает PRoot из vendored sources и проверяет x86_64 приложение на API 35 без Wi-Fi/мобильных данных. Затем матрица выпускает три APK с соответствующими образами. Размер и SHA каждого фактического CI-образа берутся из assets/runtime/*.json внутри APK, не из локальной сборки. `collect_android_sources.py` собирает точные исходники GPL-компонентов всех трёх образов.

Manifest version 2 передаёт три подписанных APK и архив исходников; Android-runtimes.json добавляется из docs/releases. Вместе с десятью desktop-пакетами, SBOM, лицензиями, сертификатом и SHA256SUMS релиз содержит 20 файлов. Publisher сверяет исходники приложения, PRoot и скрипты сборки с успешным build commit.

### Передача публичных подписей (manifest version 3)

Для крупных APK publisher загружает исходные build inputs из того же успешного CI, а не передаёт повторно все компиляторы. `apk_release_patch.py` сопоставляет сырые ZIP payloads по SHA-256: неизменные байты копируются из точного CI APK, заголовки и **публичные** подписи/сертификат передаются небольшим patch. Пароль и закрытый ключ не входят в patch. Размер и SHA-256 проверяются у базового APK, patch и конечного файла; результат побайтово совпадает с APK, подписанным владельцем локально. Неверная база и повреждённый patch отклоняются до публикации. Архив GPL-исходников передаётся прежним способом.

Три автоматические проверки покрывают изменившиеся ZIP offsets/порядок/метаданные, повреждение базы и повреждение публичной подписи. Метод дополнительно проверен на реальном APK 0.2.0: восстановлены точные 43 356 200 байт с SHA-256 `395bcd643aa70ba36bc84c1871b6286299931c8373ba4bd16114fb05dbce7527`; передано только 227 558 байт публичного patch.

### Учебники и версия 0.3.0

Manifest version 3 с asset_count: 21 добавляет DevCat-0.3.0-lectures.zip из воспроизводимого docs/DevCat-lectures.zip. Остальные 20 пакетов/сопроводительных файлов сохраняются по назначению. Build 0.3.0+4: versionCode ARM64 2004 / ARMv7 1004 / x86_64 4004, тот же постоянный сертификат. Все 21 файла входят в SHA256SUMS (сам файл сумм проверяется отдельно). Контент и учебники регенерируются и проверяются на byte diff в CI.

### Универсальный Android 0.4.0

Manifest version 4 передаёт один подписанный universal APK и исходники сред. В релизе 19 assets: десять desktop-пакетов, один APK и восемь сопроводительных файлов, включая архив 11 учебников. Три ABI-образа подготавливаются независимо и объединяются в одном Android job. Финальная команда: flutter build apk --release --target-platform=android-arm,android-arm64,android-x64 --build-number=5005. Сборка проверяет лимит GitHub 2 GiB на файл. Сохранена постоянная подпись; номер 5005 позволяет обновление с split 2004/1004/4004. Transfer workflow разбивает публичный APK максимум на восемь частей по 256 MiB. Закрытый ключ и пароль не передаются.

### Переработанный курс и компактные среды 0.5.0

Версия приложения 0.5.0+6, Android versionCode 5006; постоянный сертификат и manifest version 4 сохранены. После восстановления полного закреплённого SDK-кэша `compact_android_image.py` создаёт профиль `devcat-offline-compact-1` и пересчитывает SHA образа. Исходный кэш и закреплённые версии пакетов не меняются. Удаляются src.zip JDK, заголовки Node для native addons, шаблоны и необязательные SDK-инструменты .NET; Roslyn, reference assemblies и runtime остаются. Обязателен успешный offline Android device job на окончательном commit до публикации. Объём APK указывается только после подписи фактического пакета.

Контент всех 11 направлений и архив учебников воспроизводятся Python 3.10 без diff. В релиз идут оригинальные объяснения DevCat, а не PDF сторонних учебников; происхождение источников указано в `BOOK_SOURCES.md`.

### Учебный формат 0.6.0

Версия 0.6.0+7, Android versionCode 5007. В пакеты включается `assets/content/study_path.json`: 516 тем, 1 548 ступеней. Сверяйте этот файл с исходным commit на всех четырёх платформах наряду с лекциями. Контрактные тесты проверяют отсутствие вариантов из будущих глав, восстановление полных программ и настоящие ожидаемые результаты. Android-интеграция проверяет локальную оценку правильного и ошибочного решения нового занятия, а также объединение прогресса без дублирования XP.
