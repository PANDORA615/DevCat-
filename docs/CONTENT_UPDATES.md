# Проверка и хранение подписанного контента

Текущий этап — библиотека `core/content_update.dart`. Загрузка из GitHub, закрепление релизного публичного ключа, проверка схем учебных курсов и подключение активного снимка к приложению ещё не реализованы. Наличие этой библиотеки не означает готовность OTA в установщиках.

Конверт JSON содержит `keyId`, `payload` (Base64 точных UTF-8 байтов JSON) и `signature` (Base64 Ed25519). Проверка выполняется над исходными байтами payload до его разбора. Корневые доверенные ключи передаются извне и не принимаются из пакета.

Подписанные поля: `schemaVersion: 1`, `kind: "devcat-content"`, положительный целочисленный `revision`, `minAppBuild` и массив `files`. У файла есть `path`, `size`, строчный шестнадцатеричный `sha256` и Base64 `data`. Допустимы только плоские имена JSON/PNG/JPG/JPEG в `assets/content/`; исполняемые файлы, сценарии, вложенные каталоги, traversal и имена, различающиеся только регистром, отклоняются. Лимиты: 4 096 файлов, 96 МиБ конверта и 96 МиБ суммарных декодированных файлов. Из-за двойного Base64 эффективный предел полезных данных меньше размера конверта; это формат ограниченных обновлений, не полный дистрибутив.

Установщик повторно проверяет пакет собственными доверенными ключами, даже если объект уже проверен другим экземпляром библиотеки. Файлы записываются с flush в staging, затем каталог переименовывается в версионный. Два чередующихся указателя сохраняют предыдущую активную версию при прерывании записи. Чтение повторно проверяет подпись и соответствие файлов; повреждённый активный снимок позволяет перейти к предыдущему. Rollback также проверяет файлы целевой версии до переключения. Повторная установка после сбоя активации восстанавливает указатель; повтор уже активной версии не стирает предыдущую. После активации остаются два снимка. Отдельные пользовательские файлы не затрагиваются.

До подключения к продукту остаются проверка схем/совместимости курсов и изображений, сетевой клиент с ETag и отменой, доверенный релизный ключ, интерфейс и публикация пакетов. Обновление исполняемого приложения — отдельный механизм.

Проверка: `flutter analyze --no-pub` без замечаний; все шесть тестов `test/content_update_test.dart` прошли. Они проверяют подмену подписи/ключа, опасные пути, установку и rollback, сохранность пользовательского файла, повреждение активной версии и повторную проверку доверия установщиком. Также проверены повтор установки после потери указателя и хранение только двух активных/предыдущих снимков.
