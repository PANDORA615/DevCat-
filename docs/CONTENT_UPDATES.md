# Обновления на ПК — подготовка 0.9.1

В исходниках подключены подписанные пакеты уроков и «Настройки → Обновления» для Windows, Linux и macOS. Android сохраняет зафиксированный интерфейс 0.8.0; меняется только номер сборки. Это описание разработки, а не объявление опубликованного 0.9.1.

## Работа пользователя

Проверка доступна вручную, автоматически не чаще раза в сутки, со стабильным или предварительным каналом. ETag и подписанное описание сохраняются между запусками. HTTP 429/403 включают паузу, временные ошибки сервера — увеличивающуюся задержку. Без сети доступны встроенные уроки и прогресс.

Подписанный Ed25519 индекс связывает тег GitHub, версию, канал, номер сборки, совместимость курсов, платформы, размеры и SHA-256 файлов. Адреса формируются для PANDORA615/DevCat-, используются только HTTPS GitHub и его CDN. Клиент не хранит GitHub-токен и не принимает произвольные адреса установщиков из JSON.

Загрузка поддерживает отмену и HTTP Range. Подписанный размер ограничивает поток, SHA-256 проверяется по всему файлу. Сервер, игнорирующий Range, вызывает загрузку заново. Частичный файл сохраняется. Кэш ограничен 3 ГиБ; удаление старых загрузок затрагивает только собственный каталог обновлений.

Пакет уроков можно импортировать из файла с такой же проверкой подписи и содержимого. Одновременная установка блокируется. Новые уроки включаются после следующего запуска: открытое занятие не меняется посреди работы. Откат возвращает предыдущие проверенные уроки, после первого обновления — встроенную редакцию. Прогресс, ответы, настройки и проекты хранятся отдельно.

Перед открытием установщика повторно проверяются размер и SHA-256, сохраняются редакторы и состояние занятия. Работающая программа или ошибка сохранения останавливает переход. Пользователь подтверждает запуск. EXE/DMG/DEB/RPM открываются средствами ОС; для переносимых пакетов открывается папка с инструкцией заменить приложение после закрытия и сохранить прежний файл. Системные подтверждения, Authenticode и notarization этим механизмом не заменяются; автоматического downgrade данных нет.

## Формат и хранение

Конверт содержит keyId, payload (Base64 точных UTF-8 байтов JSON) и signature (Base64 Ed25519). Подпись проверяется над исходными байтами. Ключи закреплены во встроенном assets/branding/desktop_update_keys.json и не принимаются из обновлений.

Подписанный payload: schemaVersion=1, kind=devcat-content, положительный revision, minAppBuild и files. Файл содержит path, size, sha256, data. Допустимы только плоские JSON/PNG/JPG/JPEG в assets/content/. Сценарии, архивы, исполняемые файлы, вложенные пути, traversal и дубликаты без учёта регистра запрещены. Лимиты: 4 096 файлов, 192 МиБ конверта, 96 МиБ декодированных данных.

Валидатор требует все 11 направлений, сохранение старых ID уроков, совпадающий маршрут, поддерживаемые задания, уникальные ID занятий и вопросов. Проверяются типизированные поля вопросов, принадлежность тем курсам, ссылки на картинки, структура/CRC PNG и размеры изображений. Большие проверки и запись выполняются в isolate.

Снимок записывается с flush в staging и переименовывается в версионный каталог. Два указателя сохраняют последнюю исправную версию при прерывании активации. Чтение и откат повторно проверяют подпись и файлы. Повреждённый новый снимок не вытесняет исправную резервную копию. Пользовательские файлы не удаляются.

## Подготовка пакета

scripts/content_package.py детерминированно формирует payload из дерева исходников. На машине подписания создаётся небольшой публичный signature record. Закрытый ключ не попадает в Git, приложение или CI. CI восстанавливает идентичный JSON по исходникам и record и проверяет подпись закреплённым ключом. Изменённые после подписания исходники отклоняются.

Локальные тесты утилиты проверяют воспроизводимость без закрытого ключа, изменённые данные/подпись, символьные ссылки и конфликт имён. Выпуск должен содержать подписанный content-index.json с фактическими хешами установщиков и пакета. Старые неподписанные выпуски клиент не предлагает как автоматическое обновление.

## Оставшиеся ограничения

Формат пока обновляет курсы, задания и иллюстрации. Доставка внешностей кота, звуков, тем и локализаций через OTA ещё не реализована. Индекс и пакет 0.9.1 ещё не опубликованы. Аппаратная проверка системных установщиков — отдельная часть приёмки; модульные тесты её не заменяют.
