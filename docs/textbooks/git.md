## 1. До Git: файл, папка, сохранение и копия

01 · До первого коммита · Git / GitHub с нуля

### Сначала разберём новые слова

Путь указывает, какой файл открыть. Чтение получает его содержимое, запись меняет данные на диске. Относительный путь отсчитывается от рабочей папки запуска. Закрытие освобождает ресурс. Проверяй отсутствие файла и отказ доступа отдельно от ошибки формата данных.

Если пока трудно отличить код, ввод и результат, начни с раздела «С полного нуля» этого курса. Там каждое действие рассматривается отдельно. Не нужно понимать незнакомый термин до того, как увидел его работу.

### Объяснение с нуля

Файл — документ с именем и содержимым, папка объединяет файлы. Нажатие «сохранить» записывает текущий текст в файл, но само по себе не создаёт историю версий. Копия папки хранит ещё один набор файлов, однако не объясняет, какое изменение было сделано и почему. Git решает задачу именованной истории, а не заменяет сохранение в редакторе.

### Шаги: повтори на своём учебном проекте

Создай учебную папку. В ней создай README.md с одной строкой «Учусь». Сохрани, закрой, открой и найди ту же строку. Пока Git не нужен.

```git
README.md → текст «Учусь»
```

### Что проверить после действия

Не переходи дальше только потому, что нажал кнопку. Найди наблюдаемый результат: файл, строку status, новый коммит или изменение на странице своего репозитория. Сравни его с целью текущего шага. Если действие произошло на GitHub, локальная папка изменится только после получения истории; если действие было локальным, сайт изменится только после отправки. Прочитай адрес страницы или текущую папку терминала перед повторением команды.

### Типичная путаница и безопасное исправление

Сохранение файла, git add, commit и push — разные действия. Сначала выясни, на каком из них остановился процесс. При ошибке прочитай текст полностью и не вводи случайно reset --hard, clean или force push: они не требуются для обычного первого опыта. Для чужого репозитория отсутствие права записи не является ошибкой Git. Для private-репозитория проверь вход и выбранного владельца. Не публикуй секреты на снимках экрана.

### Самостоятельная практика

Создай учебную папку. В ней создай README.md с одной строкой «Учусь». Сохрани, закрой, открой и найди ту же строку. Пока Git не нужен.

Теперь повтори процесс в новом маленьком учебном примере без подсказки. Запиши цель, точное действие и результат. Объясни, где находятся данные после каждого шага. Для локальных команд используй компьютер; браузерные действия GitHub можно выполнить на компьютере или телефоне. Онлайн-сервис требует интернета, даже когда сама теория хранится офлайн.

## 5. git diff: видим, что изменилось

01 · До первого коммита · Git / GitHub с нуля

### Объяснение с нуля

diff показывает различия, а не полную новую копию файла. Строка с минусом удалена из сравниваемой старой версии, с плюсом добавлена в новую. Это обозначения отчёта: символы + и - не обязательно находятся в исходном файле. Обычный git diff показывает не добавленные в индекс изменения, git diff --cached — подготовленные к коммиту.

### Шаги: повтори на своём учебном проекте

После первого коммита допиши вторую строку README, сохрани и выполни git diff. Найди добавленную строку. Затем после git add сравни обычный diff и --cached.

```git
git diff
git diff --cached
```

## 18. Pull request: предлагаем и обсуждаем изменение

### Объяснение с нуля

Pull request — предложение объединить изменения одной ветки с другой. Base — целевая ветка, compare — ветка с предложением. Перед отправкой читают diff и описание. Автор объясняет проблему, поведение после изменения и проверку. Наличие PR не означает, что работа уже принята. Merge выполняет тот, у кого есть право.

### Шаги: повтори на своём учебном проекте
